# API для Clarity Project

[Опис API](README.md)

### Санкції

Методи перевіряють наявність суб'єктів у таких санкційних списках:
- `ofac-sdn` - санкційний список Міністерства фінансів США (SDN);
- `ofac-non-sdn` - санкційний список Міністерства фінансів США (Non-SDN);
- `un-sc` - санкційний список ООН;
- `eu-fsf` - санкційний список ЄС;
- `uk-fcdo` - санкційний список Великої Британії (FCDO);
- `ua-rnbo` - санкції Ради національної безпеки і оборони України.

Всі методи повертають відповідь в [однаковому форматі](#формат-відповіді).

## sanctions.search
Метод виконує пошук у санкційних списках за назвою, ПІБ, псевдонімом, 
реєстраційним номером юридичної особи чи номером паспорта фізичної особи.

##### Параметри:
* **q** - пошуковий запит;
* **type** - тип суб'єкта: `person` - фізична особа, `entity` - юридична особа, 
  `all` - всі типи (значення за замовчуванням);

##### Приклад запиту:
https://clarity-project.info/api/sanctions.search?q=приклад&type=entity&key=xxx

Метод повертає не більше 25 записів. 

Всі знайдені записи мають `match_status` зі значенням `possible-match` 
та `relation` зі значенням `direct`.

Якщо параметр `q` порожній - списки `items` всіх джерел будуть порожніми.

## edr.info/sanctions
Метод перевіряє за санкційними списками юридичну особу за її кодом ЄДРПОУ 
та пов'язаних з нею фізичних осіб: керівників, підписантів, засновників і бенефіціарів, 
в тому числі колишніх.

##### Приклад запиту:
https://clarity-project.info/api/edr.info/00000000/sanctions?key=xxx,
де **00000000** - код ЄДРПОУ.

Значення `match_status` та `relation` залежать від того, за чим знайдено запис:
- за кодом ЄДРПОУ самої компанії: `exact-match` та `direct`;
- за ПІБ пов'язаної особи: `possible-match` та `relative`. В цьому випадку 
  також заповнюються поля `relation_info` та `related_person_roles`.

Метод повертає помилку з кодом **404**, якщо компанію не знайдено, 
та з кодом **451**, якщо доступ до даних компанії обмежено.

## persons.info/sanctions
Метод перевіряє фізичну особу за санкційними списками. Пошук виконується за ПІБ 
та його транслітерацією.

##### Приклад запиту:
https://clarity-project.info/api/persons.info/00000000000000000000000000000000/sanctions?key=xxx

Де:
* `00000000000000000000000000000000` - це ідентифікатор (`hash`) особи з методу 
  [persons.search](persons.search.md#personssearch), або її ПІБ.

Всі знайдені записи мають `match_status` зі значенням `possible-match` 
та `relation` зі значенням `direct`.

Метод повертає помилку з кодом **404**, якщо особу не знайдено.

## Формат відповіді
У списку `result` завжди повертаються всі джерела. Якщо в джерелі нічого не знайдено - 
його список `items` порожній.

##### Приклад відповіді:
```json
{
  "result": [
    {
      "source_code": "ofac-sdn",
      "source_title": "Санкційний список Міністерства фінансів США (SDN)",
      "items": []
    },
    // ...
    {
      "source_code": "ua-rnbo",
      "source_title": "Санкції Ради національної безпеки і оборони України",
      "items": [
        {
          "record_id": "0000000000000000000000000000000000000001",
          "authority": "Рада національної безпеки і оборони України",
          "program": [],
          "scope": [
            "[1] Блокування активів"
          ],
          "reason": "Указ 0/2023 від 15.01.2023",
          "source_url": "https://example.com/decree-annex.pdf",
          "target": {
            "relation": "direct",
            "relation_info": null,
            "type": "entity",
            "name": [
              "ТОВ \"ПРИКЛАД\""
            ],
            "address": [
              "м. Київ, вул. Прикладна, 1"
            ],
            "birth_place": [],
            "birth_date": [],
            "citizenship": [],
            "identifications": [
              {
                "number": "00000000",
                "type": "Код ЄДРПОУ"
              }
            ],
            "related_person_roles": []
          },
          "match_status": "exact-match",
          "date_start": "2023-01-15",
          "date_end": "2033-01-15"
        },
        {
          "record_id": "0000000000000000000000000000000000000002",
          "authority": "Рада національної безпеки і оборони України",
          "program": [],
          "scope": [
            "[1] Блокування активів"
          ],
          "reason": "Указ 0/2023 від 15.01.2023",
          "source_url": null,
          "target": {
            "relation": "relative",
            "relation_info": "Керівник, Засновник",
            "type": "person",
            "name": [
              "Приклад Петро Іванович",
              "Pryklad Petro"
            ],
            "address": [],
            "birth_place": [
              "м. Київ"
            ],
            "birth_date": [
              "1970-01-15"
            ],
            "citizenship": [
              "ua"
            ],
            "identifications": [
              {
                "number": "АА000000",
                "type": "Паспорт"
              }
            ],
            "related_person_roles": [
              "director",
              "founder"
            ]
          },
          "match_status": "possible-match",
          "date_start": "2023-01-15",
          "date_end": null
        }
      ]
    }
  ],
  "stats": { }
}
```

##### Опис полів:
* `source_code` - код джерела (перелік наведено [вище](#санкції));
* `source_title` - назва джерела;
* `items` - знайдені санкційні записи:
  * `record_id` - ідентифікатор запису;
  * `authority` - орган, що застосував санкції;
  * `program` - санкційні програми, може бути порожнім списком;
  * `scope` - застосовані обмеження, може бути порожнім списком;
  * `reason` - підстава застосування санкцій, `null` - якщо відсутня;
  * `source_url` - посилання на джерело, `null` - якщо відсутнє;
  * `match_status` - ступінь збігу: `exact-match` - точний збіг, `possible-match` - можливий збіг;
  * `date_start`, `date_end` - дати початку та завершення дії санкцій, `null` - якщо відсутні;
  * `target` - суб'єкт санкцій:
    * `relation` - зв'язок з об'єктом перевірки: `direct` - прямий, `relative` - через пов'язану особу;
    * `relation_info` - опис зв'язку з компанією, для прямого зв'язку `null`;
    * `related_person_roles` - ролі пов'язаної особи в компанії: 
      `director`, `signer`, `founder`, `beneficiary`, для прямого зв'язку порожній список;
    * `type` - тип суб'єкта: `person` - фізична особа, `entity` - юридична особа;
    * `name` - імена або назви суб'єкта;
    * `address` - адреси;
    * `birth_place` - місця народження;
    * `birth_date` - дати народження у форматі `YYYY`, `YYYY-MM` або `YYYY-MM-DD`;
    * `citizenship` - громадянство, двобуквені коди країн ISO 3166-1 в нижньому регістрі;
    * `identifications` - документи та реєстраційні номери суб'єкта: 
      `number` - номер, `type` - тип, текстове значення з джерела;

Поля `birth_place`, `birth_date` та `citizenship` заповнюються лише для фізичних осіб.
