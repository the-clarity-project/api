# API для Clarity Project

[Опис API](README.md)

### Дані ДАБІ

Методи працюють із наявними у Clarity даними про дозвільні документи на будівництво та їх учасників. Кожен запит потребує API-ключа в параметрі `key`; для нього застосовуються чинні ліміти й облік використання публічного API. Кожен успішний виклик списує один запит, а відповідь містить `stats` із часом виконання та використаною квотою.

## construction.search

Пошук документів за текстом і фільтрами. Усі параметри пошуку необов'язкові та можуть поєднуватися.

##### Параметри:
* **search** - повнотекстовий запит;
* **entity** - код учасника або його назва чи ПІБ. Числове значення шукається за кодом, інше — за хешем переданої назви;
* **hromada** - код КАТОТТГ громади;
* **date_from** - нижня межа дати документа включно, `YYYY-MM-DD`;
* **date_to** - верхня межа дати документа включно, `YYYY-MM-DD`. Межа встановлюється на початок зазначеного дня за часом Києва;
* **class** - клас наслідків: `1`, `2` або `3`;
* **doc_type** - код типу документа з переліку нижче;
* **page** - номер сторінки; за замовчуванням `1`.

Неправильні значення дати, `class` та `doc_type` не застосовуються як фільтр. У поточній реалізації доступність наступних результатів обмежена налаштуваннями пошуку; для широких запитів уточнюйте фільтри.

Значення `doc_type`:

```text
preparatory-notice, preparatory-notice-change, preparatory-declaration,
preparatory-declaration-change, construction-notice, construction-notice-change,
construction-notice-cancellation, construction-declaration,
construction-declaration-change, permit, permit-change, permit-annulment,
readiness-declaration, readiness-declaration-change,
readiness-declaration-cancellation, readiness-declaration-technical-error,
court-readiness-declaration, amnesty-readiness-declaration, certificate,
data-change-letter
```

##### Приклад запиту:

https://clarity-project.info/api/construction.search?key=xxx&entity=25412361&page=1

Відповідь містить `result.items` — сторінку документів, `result.total` — кількість результатів пошуку, а також `page`, `perPage`, `limit` і `offset`. За замовчуванням сторінка містить до 25 результатів. Для наступної сторінки повторіть запит із тими самими фільтрами та наступним значенням `page`.

## construction.document/{id}

Повертає картку документа з учасниками. `id` — значення `hash` із результатів пошуку.

##### Приклад запиту:
https://clarity-project.info/api/construction.document/00b5346334e6922876a683f1e9c0714d?key=xxx

Відповідь має вигляд `{ "result": { ... }, "stats": { ... } }`, де `result` має ті самі поля документа, що й елемент `result.items` пошуку. Відсутні значення можуть бути `null`; `parties` — список учасників із роллю, типом, назвою або ПІБ, кодом і свідоцтвом за наявності. Для невідомого хешу повертається HTTP 404.

Ланцюжок «пошук → документ»: виконайте `construction.search`, виберіть `hash` із потрібного елемента `items`, а потім передайте його в `construction.document/{id}`.

## construction.examinators/{edrpou}

Повертає записи «Обстеження об'єктів будівництва» про експертів, пов'язаних із компанією за кодом `edrpou`. Це окремі записи про експертів і свідоцтва, а не список учасників конкретного документа.

##### Приклад запиту:
https://clarity-project.info/api/construction.examinators/25412361?key=xxx

##### Приклад відповіді з тестовими даними:

```json
{
  "result": [
    {
      "certificate_number": "АЕ000001",
      "expert_name": "ТЕСТОВИЙ ЕКСПЕРТ",
      "consequence_classes": "СС1, СС2",
      "date": "2021-04-21",
      "description": "Тестовий запис про експерта з обстеження об'єктів будівництва",
      "source": "Тестові дані"
    }
  ],
  "stats": { "query_time": 0.15, "quota": { "used": 10, "max": 100, "key_used": 10 } }
}
```

`date` — дата публікації запису в досьє, а не обов'язково дата свідоцтва. Якщо записів немає, `result` дорівнює `[]`.

## Пов'язані методи

Ланцюжок «компанія → документи»: передайте код компанії в `construction.search` як `entity`, перегляньте `construction_count` та `result.items`, а за потреби відкрийте картку за `hash`.

У [persons.info](persons.search.md#personsinfo) поле `list[ідентифікатор].dabi` за наявності містить участь особи у документах ДАБІ: роль (`Role`, `RoleName`), ім'я (`Name`), код (`Edr`), свідоцтво (`Cert`) і кількість записів (`Count`). Поле може бути відсутнім, якщо таких даних немає.

Будівельні ліцензії компанії чи ФОП доступні через наявний [edr.info/{edrpou}/licenses](edr.info.md#edrinfolicenses). У відповіді `list` повертаються, зокрема, реєстр, вид діяльності, орган ліцензування та дати дії; метод охоплює ліцензії загалом.

## Помилки та актуальність

Типова помилка повертається як `{ "code": 401, "text": "No api key is provided" }`. Залежно від причини можливі HTTP 401 — відсутній або некоректний ключ, 403 — ключ неактивний, 402 — вичерпано ліміт, 404 — документ не знайдено, 500 — внутрішня помилка. Повідомлення може містити додаткові подробиці.

Дані походять із доступного набору дозвільних документів ЄДЕССБ та інших наявних у Clarity джерел. Оновлення набору й індексу заплановано щодня, але фактична свіжість залежить від джерела та успішності обробки; повнота і миттєве оновлення не гарантуються. Записи про експертів беруться з окремої зовнішньої інформації компанії та можуть оновлюватися за іншим графіком.
